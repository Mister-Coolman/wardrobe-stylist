1Intent

The problem, firsthand: “I own plenty of clothes and still wear the same few things.” Every morning is a decision made without knowing what the day holds. Packing for a trip is the same problem multiplied by every day away.

The product: film your closet once and the app builds a digital wardrobe. Each morning it reads your calendar and the weather, asks about anything that isn’t on the calendar, and proposes an outfit from clothes you own — explaining why, and optionally rendering it on you. For trips it plans each day and builds a packing list that respects how often you’re willing to rewear each kind of garment.

Success criteria

  • Judges can open a deployed link and use a working product.
  • The 3-minute demo shows: closet scan → daily outfit with visible self-correction → “anything else today?” → trip packing → closet gap card.
  • At least four Meta models, each doing something distinct: SAM 3.1, Muse Spark, Muse Image, Muse Voice Transcribe (plus Model API search grounding).
  • Everything shown was built 27 Oct – 4 Nov, provable from the public repo’s commit history.

4Closet scan

CaptureSweep pan across the closet · Hold-up show items one at a time · Photo single item. A photo is a one-frame video; all three share one pipeline.
UploadTo Storage; a ScanJob reports progress (“Found 14 · tagging 6/14”).
Segment — SAM 3.1Text prompt “clothing item” on the video → each garment tracked across frames under one ID.
Best framePer garment, pick the largest and sharpest mask → transparent PNG cutout.
Tag — Muse SparkCategory, subcategory, colors, pattern, formality, warmth, tags — schema-validated, retried once, else left for manual tagging.
DedupeSimilar candidates compared by Muse Spark (“same item?”).
ReviewYou confirm, fix tags or delete. Only confirmed garments are used by the stylist.
Day-1 risk check (when API credits arrive): run one real closet video through SAM 3.1 and confirm text prompts on video, the mask format and size limits.

5Stylist agent

The outfit loop — run by our code in a fixed order

Gather contextEvents (calendar + ones you added) · weather at the event or home location · eligible garments
ProposeMuse Spark returns 3 candidate outfits as JSON: garment IDs + a “why” for each piece
Check → reviseEvery rule checks every candidate. If all fail, the violations go back to Muse Spark to revise (max 2 rounds).
PickRank survivors by rule soft-scores + the model’s ranking
RenderMuse Image in your render mode; on failure or timeout, fall back to the piece grid
Store & showOutfit with its rule report and revision log — shown in the UI as “fitting notes”

Rules

Each rule is one file implementing { id, kind: hard | soft, check(outfit, ctx) → violations[], score?(outfit, ctx) }. Adding a rule means adding a file to the registry.

RuleKindWhenWhat it checks
completenesshardMVPTop + bottom (or one-piece) + shoes
formalityhardMVPMatches the day’s most formal event
weatherhardMVPWarmth vs. temperature; nothing rain-unsafe at ≥50% rain
availabilityhardMVPEvery piece is clean
wearLimithardTripsUses per garment ≤ its rewear limit
capsuleReusesoftTripsFewer distinct items scores higher
noRepeatWithSamePeoplehardLaterNot worn recently in front of the same attendees
laundryCyclehardLaterMoves items to laundry when they hit their limit

Daily flow

  • The day’s most formal event sets the dress code. A big gap between events (gym → client meeting) produces a change-of-clothes suggestion.
  • After the first outfit appears, the card asks: “Anything else today that’s not on your calendar?” Quick chips (gym, dinner out, date, outdoors, nothing) or voice / text. Answers become Event(source: user) and the loop runs again.
  • “I wore this” writes a WearLog entry and updates the wear counts.

Chat agent

Muse Spark with tools: get_events, get_weather, search_wardrobe, plan_outfit, plan_trip, log_wear, add_event. Voice comes in through the transcriber. Free-form requests become tool calls; outfits always come from the outfit loop, never straight from the chat model.

Trip packing

Input: destination and dates, or detected from calendar events (“Flight to ORD”). For each day, the destination’s weather plus any trip events go through the outfit loop with wearLimit and capsuleReuse. Output: day-by-day outfits, a packing checklist (each garment and how many days it’s used), and a warning when your wardrobe can’t meet the limits (“you own 3 clean t-shirts for 5 days”).

Closet gap card

Muse Spark proposes 3 items you might be missing. Our code counts, for each one, how many new rule-passing outfits it would make possible — the model can’t invent that number. The best one is matched to a real product through Model API search grounding. Shown as one card, not a feed.

7Error handling & testing

Error handling

  • Every model call has a timeout and a typed error; the UI names the failure and offers a retry.
  • A failed render falls back to the piece grid and never blocks the outfit.
  • Stylist output is schema-validated; unknown garment IDs count as violations.
  • Too few garments for a valid outfit → say which category is missing (feeds the gap card).
  • No calendar → manual events only. No weather → ask “warm, mild or cold?”.

Testing

  • Unit tests for every rule with fixture outfits.
  • Outfit-loop tests with a mock stylist — including one that breaks rules, to exercise revision.
  • Trip planner: satisfiable and unsatisfiable rewear limits.
  • Adapter contract tests against fixtures; a manual smoke script for the real APIs.
  • 3 Nov: run every demo step against the real APIs.
